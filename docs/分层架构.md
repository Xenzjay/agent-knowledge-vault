# 信息架构

## 设计目标

用稳定、可理解的分类承载日常记录、参考资料、长期知识和持续工作；同一套目录既便于人工浏览，也便于 Agent 判断写入位置。

## 层级模型

| 层级 | 表达内容 | 示例 |
|---|---|---|
| 大区 | 信息性质或生活/工作领域 | 资源、知识、工作台 |
| 主题 | 长期稳定的内容类型 | GitHub仓库、技术、项目 |
| 子主题 | 大主题下具有独立检索或维护需要的分组 | AI与智能体、运维与部署 |

默认 scaffold 创建前两层。manifest 中的子主题作为可选扩展，通过 `-IncludeSuggestedSubgroups` 生成。

## 完整大区与二级分类

完整机器可读定义见 `manifest/vault-manifest.json`。默认分类如下：

| 大区 | 二级分类 |
|---|---|
| 收件箱 | 速记、待办、待读 |
| 笔记 | 灵感、读书、学习、随笔、创作、自媒体 |
| 资源 | 网站、工具、GitHub仓库、剪藏、娱乐、素材、表情包、壁纸 |
| 知识 | 技术、方法论、调研、生活、办事、人文 |
| 工作台 | 项目、智能体与AI、自动化、实验、基础设施 |
| 事务记录 | 账号、个人档案、订阅 |
| 健康 | 健身、饮食、医疗健康 |
| 财务 | 收支记录、投资理财、保险 |
| 家庭与生活 | 家务、宠物、人际、旅行、礼物 |
| 归档 | 项目、知识、生活、年度 |
| 待整理区 | 未分类、待确认、待删除 |

## 分类原则

- 按内容的主要用途选择一个主位置；需要多入口时用标签和双链，不复制文件。
- 有稳定主题且值得单独筛选时才创建子主题。
- “最近、重要、待读、临时”等属于状态，使用属性、标签或查询表达。
- 项目可拥有独立工作区；其他分类不因单条内容而继续拆分。
- 归档用于停止活跃维护的内容；待整理区是临时队列，定期清空。

## 可配置性

可直接修改 manifest 中的大区、分类、显示名称和建议子主题。若调整目录名，应同步修改路由规则和已有链接迁移策略。
